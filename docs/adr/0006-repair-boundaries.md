# ADR 0006: граница deterministic repair

- Статус: заменено [ADR 0007](0007-typed-agentic-workflow.md)
- Дата: 9 августа 2026 года

## Контекст

Один repair-класс одновременно выполнял локальные безопасные правки и полностью
заменял кандидата канонической реализацией семейства. Это затрудняло аудит:
удаление markdown fence и генерация нового ISO-конвертера выглядели одинаковыми
действиями, хотя их влияние на исходный ответ принципиально различается.

## Решение

Канонические замены вынесены в `CanonicalFamilyRepairer` с закрытым перечнем
поддерживаемых action codes. Общий `DeterministicRepairer` оставляет локальные
синтаксические преобразования рядом с repair loop и явно делегирует полную
семейную замену через эту границу. Неизвестная canonical action завершается
ошибкой, а не выбирает неявный шаблон.

## Последствия

Поведение pipeline и внешний контракт не меняются. Канонические ответы больше
не смешаны с минимальными преобразованиями в одном модуле, их можно отдельно
учитывать в ablation/evidence и независимо проверять contract tests.
