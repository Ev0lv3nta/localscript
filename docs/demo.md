# Сценарии использования

Запустите сервис и откройте http://127.0.0.1:8080/. В шапке отдельно видны доступность API и готовность модели. Время ответа зависит от модели и GPU; фиксированное обещание «демо за минуту» здесь не используется.

## Новая задача

Загрузите пример обработки массива или введите собственный prompt и JSON context. После генерации покажите Lua, значение в блоке «На ваших данных» и сводку выполненных проверок. Если код не прошёл проверку, поле code не публикуется.

Затем измените задачу и повторите генерацию: новая задача должна получить новую сессию. Прежний код не должен выглядеть ответом на новый запрос.

## Уточнение и правка

В контексте могут одновременно присутствовать wf.vars и wf.initVariables. Если сервис спрашивает источник, ответьте на конкретный вопрос и продолжите сессию. Если не хватает данных, заполните JSON-контекст перед продолжением.

После ответа можно раскрыть «Уточнить уже полученный результат» и передать feedback. Подтверждённые условия и предыдущий принятый код сохраняются для правки. После десяти пользовательских ходов сервис просит новую сессию вместо забывания ранних требований.

## Самостоятельная validation

Кнопка «Проверить ещё раз» использует output contract полученного ответа. Она не вызывает модель, а запускает уже выданный код на текущем context.

В API тот же режим доступен через POST /api/validate. Без expected он проверяет исполнение и форму; для семантического сравнения нужны явно заданные ожидания.

## Проверка перед демонстрацией

Пройдите последовательно обработку массива, агрегацию/объект и уточнение источника. Проверьте копирование cURL с кавычками, новую сессию после смены примера и понятное сообщение при недоступном backend. Не останавливайте общий Ollama ради показа ошибки; используйте отдельное тестовое окружение.

Скриншот с результатом снимается с настоящим model backend. Mock API нужен для проверки интерфейса, но его ответы не являются примером качества модели.
